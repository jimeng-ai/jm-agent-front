# Agents 与数据连接工作台 UI/UX 重设计

日期：2026-09-27
仓库：`jm-agent-front`
范围：Agents、数据连接、Agent 数据连接授权、语义层管理台
## 1. 背景

Agents 与数据连接已经具备完整业务能力，但管理界面仍主要由原生 Ant Design 表格、横向 Tabs、固定宽度 Transfer 和长 Modal 组成。随着技能、连接授权、写策略、出库档位、结构快照与语义层逐步加入，界面出现了四类问题：

1. Agent 列表缺少搜索、筛选、未发布改动提示与稳定的实体识别；每行同时平铺五个操作。
2. Agent 编辑器把“随草稿保存”的配置与“即时生效”的技能/连接授权混在同一组 Tabs 和顶部动作中。
3. 数据连接列表横向铺开十个信息维度和最多七个操作，1280–1440px 下必须横向滚动。
4. 语义层的信息正确但层级过重；生成状态、完整度、可信来源、模型可见性和危险操作主要依赖 Alert、Collapse 与宽表堆叠。

本次重设计采用已经确认的“沉浸式工作台”方向：深墨色工作区身份、克制的蓝绿语义色、明确的实体卡片、稳定的纵向配置导航和按需展开的证据 Inspector。目标不是换皮，而是重组每天真正使用的路径。

## 2. 目标与非目标

### 2.1 目标

- 让少于 20 个 Agent / 连接的日常管理更易辨认、更少滚动、更少误操作。
- 在 1280px 宽度下移除 Agents 与数据连接主页面的横向滚动。
- 明确区分 Agent 草稿保存、发布和即时授权三种生效模型。
- 让连接列表优先回答“能否安全使用”，详细结构、语义与审计按需展开。
- 将语义层提升为一级管理能力，完整保留可信来源、完整度、模型可见性和审计证据。
- 不改变现有后端接口、鉴权、安全边界、动态 schema 和 wire/model 转换契约。

### 2.2 非目标

- 不重构 AI 对话生成 Agent 的完整生成流程，只统一入口和视觉语言。
- 不合并或删除旧 `/console/connections` 兼容页面；仅澄清它与新版数据连接的关系。
- 不新增后端接口、数据库字段、批量操作或跨 Agent 的全局授权关系图。
- 不改变写策略、出库档位、凭据审计、结构刷新、语义生成和删除的业务语义。
- 不做移动端专用产品；保证 1024px 以上桌面可用，窄屏采用单列和整页 Inspector 降级。

## 3. 视觉与交互原则

- 延续 Atlas 的 slate / cobalt / emerald 色系；深墨色只用于工作区身份与证据 Inspector。
- 单页只保留一个主 CTA。低频操作进入 `···` 菜单，危险操作进入独立危险区。
- 状态必须同时使用文字或图标，不依赖颜色独立传达。
- 动效控制在 140–180ms，只用于卡片悬停、Inspector 切换、状态更新和列表过滤。
- 使用现有字体栈和本地资源，不引入远程字体、图片或动画依赖，兼容私有部署。
- 所有动画支持 `prefers-reduced-motion`。

## 4. 信息架构

### 4.1 侧栏

- `Agents` 保持一级入口。
- `数据连接` 保持一级入口，作为类型感知、含治理与语义层的主入口。
- 旧 `外部连接` 改为明确的兼容名称，例如“HTTP 出站（兼容）”，并通过说明文案指向新版数据连接。
- `写操作审批` 保持独立待办入口。
- 当权限接口已经确认当前用户不是企业超管时，隐藏数据连接、兼容连接和写操作审批入口；请求失败仍 fail-open，后端继续作为安全边界。

### 4.2 路由

- 保留 `/console/agents`、`/console/agents/:id` 和 `/console/connectors`。
- 数据连接列表的 Inspector 状态进入 URL：`?connector=<id>&tab=overview|schema|semantic|audit`，便于刷新和复制链接。
- 增加 `/console/connectors/:id/semantic` 作为完整语义层工作台的可深链入口。
- Inspector 的语义层页签提供摘要与“打开完整语义工作台”入口；语义条目审查在宽版工作台完成。

## 5. Agents 设计

### 5.1 Agent 列表

列表改为两列自适应实体卡片；低于断点时降为一列。页头包含工作区摘要、Agent 总数、已发布数和待发布数，右侧保留唯一主 CTA“新建 Agent”。

工具栏提供：

- 按名称、用途、代号或模型搜索；
- 全部、待发布、草稿筛选；
- 明确的真实空状态、过滤空状态和接口错误状态。

卡片显示：

- 首字或头像、名称、代号、模型；
- 两行内用途描述；
- 已发布 / 草稿与 `hasUnpublishedChanges` 独立状态；
- 知识库、技能、数据连接等已能从现有数据得到的摘要；
- 主动作“继续配置 / 查看变更 / 继续创建”；
- 调试、分享、发布/下架、删除进入更多菜单。

删除等危险动作保留确认；每个 mutation 只让当前卡片进入 loading。

### 5.2 Agent 编辑器

顶部实体头吸顶，包含返回、头像、名称、发布状态、未保存状态、调试、保存草稿和发布更新。长 Prompt 或表单滚动时，动作始终可见。

左侧配置导航分为两组：

1. Agent 配置：基础信息、人设 Prompt、模型参数、知识库。
2. 即时授权：技能、数据连接。

中间区域每次展示一个主题，表单宽度一致。右侧发布检查显示身份信息、模型、知识库、技能和连接的当前摘要；低于 1024px 时折叠到内容顶部。

保存语义必须明确：

- 基础信息、Prompt、模型和知识库随“保存草稿”提交。
- 技能和数据连接授权调用各自接口，即时生效；组件内显示“保存中 / 已生效 / 保存失败”。
- 即时授权不计入草稿表单的脏状态。
- 普通配置存在未保存变更时，离开页面需要确认。

保存或发布成功后同时失效：

- `['agent', 'detail', id]`
- `['agent', 'list']`
- `['chat', 'agents']`

这样返回管理列表或对话首页时不会在 30 秒 fresh window 内看到旧数据。

### 5.3 Agent 数据连接授权

固定宽度 Transfer 改为双栏授权选择器：左侧可授权连接支持搜索和状态提示，右侧显示当前授权。连接卡必须显示健康、只读验证、语义层关键状态和明确的即时生效说明。

普通成员若无法读取超管专属连接列表，组件显示真实权限说明或错误，不再把失败静默转换为空列表。

## 6. 数据连接设计

### 6.1 卡片总览

页头显示连接总数、健康数、需处理数和生成中数。工具栏提供名称/类型/能力搜索，以及需处理、类型、健康、写策略和语义层筛选。

连接卡以固定位置展示“四段安全轮廓”：

1. 账号权限 / 只读验证；
2. 平台写策略；
3. 语义层状态与完整度；
4. 数据出库档位。

卡片头显示名称、技术标识、连接类型、启用状态和健康状态。存在异常时直接写出后果和唯一下一步；例如语义层残缺要说明“缺掉的表和字段模型看不到，它不会报错，只会用已有部分拼出答案”。

主动作是“打开连接 / 查看缺口 / 重新测试”，其它动作进入 `···`。列表不再承担全部结构和审计证据。

### 6.2 统一 Inspector

点击卡片打开连接 Inspector。Inspector 包含：

- 概览：安全边界、能力、最近验证、当前风险和最近使用；
- 结构：复用并重排结构快照、漂移和刷新影响；
- 语义层：显示状态、完整度摘要与进入完整工作台的入口；
- 使用记录：复用审计查询和失败筛选。

各页签按需请求，未打开时不加载。Inspector 的当前连接与页签写入 URL。1280px 以上使用右侧宽 Inspector，窄屏使用整页呈现。

### 6.3 新建 / 编辑连接

640px 长 Modal 改为宽版分区 Drawer，左侧提供可自由跳转的四段目录：

1. 基本信息；
2. 动态连接参数；
3. 安全与治理；
4. 测试并创建。

它不是分步落库的向导：所有字段在本地保留，最终仍调用一次 create/update，避免产生半成品连接。

必须保留：

- 后端 schema 驱动的类型与参数字段；
- 敏感凭据“已保存 / 查看 / 更换”的审计式状态；
- 写策略三档和完整风险说明；
- 数据出库档位三档和逐档出库说明；
- DBA 授权命令生成器；
- 独立测试连接与就地结果；
- 相同目标连接的持久提示；
- 未知后端枚举的原值保留与兜底说明。

测试结果与当前表单内容绑定。成功后修改主机、端口、库名、凭据、写策略或其它影响探测结果的字段，结果立刻标为“配置已变化，需要重新测试”。

成功文案按实际 `readonlyVerified` 和写策略生成，不能对允许写入的连接误报“只读已验证”。

## 7. 语义层工作台

### 7.1 顶部状态

连接级生成状态与 coverage 是两个独立轴：`READY + PARTIAL` 必须同时表达“已生成并正在使用”和“说明书不完整”。

五种状态全部保留：

- `NONE`：未生成，提供开始生成；
- `RUNNING`：显示本次开始时间，只在此状态每 5 秒刷新；
- `READY`：显示条目数与最近一次成功时间；
- `FAILED`：连接仍可用，保留上次成功内容和时间；
- `NOT_APPLICABLE`：明确说明这种连接器没有结构自描述能力，不需要处理。

未知状态显式显示。`semanticNote` 保留在“本次生成详情”中，不丢失后端原始说明。

### 7.2 Coverage 与出库档位

`PARTIAL` 单独显示覆盖缺口、成因与后果；`COMPLETE` 不占警示位，空值表示没有跑过而不是残缺。四类已知 gap 和未知 gap 都保留。

当前 `semanticDataTier` 在工作台顶部常驻。对多态关联、复合键、样本值等内容，界面必须明确区分：

- 模型此刻真实可见的值；
- 平台留存但被当前档位挡住、模型不可见的值；
- 档位允许但尚未成功取得的值。

修改档位只链接回连接编辑，不在语义层工作台中新增第二个配置入口。

### 7.3 Scope 与可信链

左侧 Scope 顺序固定为：业务口径、待澄清歧义、表用途、字段含义、表关系；未知 scope 放在末尾。增加纯前端派生的“需关注”视图，用于汇总 STALE、数据不支持、无法验证、JOIN 未验证、多态/复合键和键值对表。

中央条目列表以 gloss 为视觉主体，同时保留：

- 锚点与 JOIN 目标；
- `HUMAN / IMPORTED / INFERRED` 来源；
- evidence、verified、status；
- 回答人和时间；
- 多态、复合键、表形态与模型可见条件。

右侧证据 Inspector 分为：

1. 模型此刻读到；
2. 平台留存但模型当前看不到；
3. 信任与来源；
4. 危险区。

`HUMAN` 行显示回答人、时间、Trace 和覆盖历史。STALE 对 METRIC 与其它 scope 的不同注入后果必须保持。超过现有阈值继续分页，不一次渲染全部条目。

### 7.4 重新生成与删除

重新生成保持现有语义：

- 只覆盖 `source=INFERRED`；
- HUMAN 与 IMPORTED 不变；
- 明确说明有无结构快照时对客户库的访问代价；
- 返回只表示任务已派发，不代表生成完成；
- RUNNING 防止重复派发，NOT_APPLICABLE 禁止生成并解释原因。

删除移动到右侧 Inspector 危险区，降低误触，但确认文案完整保留：物理删除不可恢复、机器推断下次可能回来、人工确认删除会同时丢失覆盖留痕。`removed=0` 继续如实提示“已经不在”，不报假成功或假失败。

## 9. 状态、错误与性能

- 列表使用骨架卡；空数据、过滤为空和请求失败分别显示。
- 请求失败提供原因和重试；后台刷新失败保留上次成功内容。
- 每个 mutation 只让当前实体进入 loading。
- 数据连接列表仍只在任一语义任务 RUNNING 时轮询。
- 语义工作台 RUNNING 时轮询连接详情与语义行，结束或离开页面立即停止。
- Inspector 各页签懒加载；Agent / 连接少于 20 条时搜索和筛选在前端完成。
- 所有未知 enum/scope/gap/detail 字段显式兜底，不静默丢弃。

## 10. 响应式与可访问性

- 重点验证 1440×900、1280×800 和 1024px。
- 卡片由两列降为一列；窄屏 Inspector 变为整页，编辑器发布摘要折叠到顶部。
- 所有可操作卡片、场景入口和菜单使用真实 button/link，支持键盘、焦点环和 ARIA 名称。
- 状态不只靠颜色表达；删除图标等纯图标动作必须有 Tooltip 和 `aria-label`。
- reduced motion 下关闭位移、闪烁和非必要过渡。

## 11. 验证

静态门禁：

```bash
npm run typecheck
npm run lint
npm run build
```

现有 E2E 需要更新为语义选择器，删除固定列号断言。重点实跑：

- Agent 搜索、筛选、打开编辑、脏状态离开确认、保存、发布、即时授权；
- 连接搜索、异常筛选、打开 Inspector、按需加载四个页签；
- 新建 / 编辑 Drawer 的动态 schema、凭据状态、写策略、出库档位、测试结果失效；
- 语义层 NONE / RUNNING / READY / FAILED / NOT_APPLICABLE、PARTIAL、请求错误和旧内容保留；
- 超管与普通成员的侧栏、连接访问和授权视角；
- 1440、1280、1024 三个宽度，以及键盘和 reduced-motion。

## 12. 验收标准

- 1280px 下 Agents 与数据连接主页面无横向滚动。
- 高频动作最多两次点击可达；低频和危险动作不再并排占用主列表。
- Agent 草稿保存、发布和即时授权的生效模型在界面上无歧义。
- 连接卡能一眼读出健康、账号权限、平台写策略、语义层和出库档位。
- 语义层现有状态、coverage、来源、验证、结构形态、Trace、覆盖历史和删除语义全部保留。
- 加载、空、错、刷新失败和未知枚举不会互相伪装。
- typecheck、lint、build 与相关 E2E / 手动路径全部通过。
